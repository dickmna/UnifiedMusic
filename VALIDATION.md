# Validation — 2026-11-13

## Completed

- Release x64 build of Harmonia 0.5.0 `UnifiedMusic.dll` and `UnifiedMusicInspect.exe` using MSVC 19.44 / VS 2022 and pinned dependencies. No embedded CME/MTD, JsonCpp, SimpleIni, playback hooks or trampoline initialization. Technical filenames and supported runtimes remain unchanged.
- 170 synthetic scanner test methods passed: the previous 129 ambient/parser/combat/condition tests plus 41 regional-guard and area-assignment tests. Multiple subcases and input-order permutations are included. The complete current log is `tests/latest-results.txt`.
- New tests cover unanimous versus partial regional exclusions, separate vanilla dragon conditions, independent two-land unions, pure-area versus quest/multiple-area/OR replacements, script/Boss sharing, changed audio, deliberate removals, malformed condition references/tails, and padding normalization. Area tests cover CELL/WRLD/LCTN, null baselines, reordered masters, parent-before-child assignments, independent overwrites, direct/transitive reversions, competing choices, clears, deleted/missing music types, missing/cyclic dependencies, and ignored/partial/malformed records. REGN recovery is deliberately excluded.
- Condition cases cover independent A/B exclusion union, semantic comparison equivalence, player references, ignored padding, master-table normalization, original-prefix changes, metadata/audio changes, OR/alias/unknown functions, deleted/unresolved areas, script/Boss/palette protection, existing union patches, and direct/transitive dependency removals. A regression verifies that a patch removing only a battle-list contribution through an intermediate dependency disables both list and condition recovery.
- Read-only inspection of 94 installed plugins with the 0.5 inspector completed in approximately 2.6 seconds. It produced zero ambient additions, battle groups, condition unions, generic guards, and assignment repairs. Orsinium's special music remained excluded; its original-track changes were rejected as protected sharing or unsupported condition extensions. This tests preservation for this sample, not a successful real-world repair.
- Reviewing the first assignment candidates identified 11 already-correct parent/child chains, including Creation placeholder cells and Anise's cabin. The final planner excludes unchanged ancestors of the assigning author; a regression test covers that distinction. These 11 records are not reported as installed conflicts or repaired records.
- Source review covered typed disk/native condition comparison, winning-source selection, required-track and policy-witness checks, preparation before battle commit, game-heap allocation, cleanup of uncommitted nodes, and append-only condition ownership. Area recovery checks the winning source and existing pointer and only changes the music slot/extra. Playlist snapshots detect earlier runtime track additions, clears or replacements. These native checks were reviewed and compiled, not executed inside Skyrim.
- Neither the game Data directory, load order, nor saves were modified.
- The earlier 0.4 offline rehearsal re-read the music records in all 94 installed plugins and matched the saved extraction; hashes of 14 Creation plugins and 13 extracted BSAs also matched. It represented all 65 winning music types supplied or overridden by those Creation plugins in 396 conditional-eligibility scenarios, plus 48 stage/location boundary inputs for six actual scripted Boss-music gates. Its scanner plan was empty. The 0.5 validation reran the full plugin scanner, not the script-condition rehearsal; both versions propose no installed changes.
- The rehearsal decoded 11,147 Creation VMAD script instances and 1,984 quest-fragment mappings without parsing errors. It resolved 97 direct MusicType Add/Remove call sites to actual music forms, inspected all 33 music-bound script classes, and checked the selected script names for loose-file or same-name archive overrides. The local condition evaluator passed 30 sanity checks; this is not a Papyrus VM or native audio-manager test. Paid scripts, plugin records, audio and detailed local evidence were not added to this repository.
- Actual-record counterexamples were found in the installed content: Orsinium permits overlapping ordinary/special candidates at some quest stages and has empty default-battle candidate sets in some supplied states; several assigned Crone exploration lists retain only silent tracks at night. These are pre-existing authored conditions, left unchanged. Supplied cross-quest states do not establish playthrough reachability, and an empty candidate set in one music type does not establish global silence.

## Not completed and limits

- No Skyrim process was launched. Native condition-node/extra-data allocation, source-file resolution, runtime prechecks, cell loading, playback, entering/leaving areas, quest changes, combat end, and save/reload remain unverified. Scanner tests do not execute the SKSE adapter or audio manager.
- Nexus 89099's complete ESP variants were not downloaded and compared record by record. This release is not certified to replace Music Patch for New Lands. Existing authored patches remain needed for unsupported logic or unverified combinations.
- Lorkhan and Chapter II were not installed for testing. Same-path audio replacements are outside scope.
- Original-track exclusion recovery rejects OR expressions, changed original conditions, non-geographic additions, changed audio/metadata, direct or transitive removals, and shared/scripted/Boss/palette tracks. New generic guards additionally require unanimous ordinary-track policy and a pure positive-area replacement. These narrow rules do not cover every new-land music patch.
- Area recovery requires a unique non-null authored assignment versus an independent inherited baseline. Two distinct new choices, deliberate dependent reversions, REGION sound-entry rules, and worldspace inheritance behavior are outside automatic reconciliation. An independent author's intention to retain the baseline cannot always be distinguished from accidental copying.
- Track presence does not prove audio-file availability or that an alternative is playable in every quest state. Unsupported script behavior and another DLL's changes may remain outside static discovery; semantic comparison checks the recognized winning track at startup only.
- The original global `MUSCombat` remains a deliberate exception to whole-type VMAD protection because default cleanup scripts may refer to it. Direct references to tracks and sharing with other protected types still prevent automatic changes.
- No MTD INI or CME JSON rules are read or generated. Config-only packs need their original framework. Earlier runtime playlist changes are detected before restoration, but later framework writes, priority changes and playback hooks are not controlled. Co-installation and initialization order remain unverified.

This is an experimental alpha, not universal music compatibility certification.
