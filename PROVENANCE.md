# Provenance

Harmonia was named UnifiedMusic through version 0.4; the technical repository and DLL names remain UnifiedMusic. The repository is AGPL-3.0-or-later. Attribution and retained license copies do not relicense third-party contributions.

- **Music Type Distributor**: ThirdEyeSqueegee; `stop-sine/MusicTypeDistributor-RE`, commit `9a4cdf112c64bff91bec8f834c62bd00c46d2fe1`. Original GPL-3.0-or-later, exceptions and manifest are retained in `vendor/MTD`. Version 0.6 introduced the existing-type INI adapter. Version 0.11 uses SimpleIni and adds clear-then-append, Location music-pointer assignment and existing Region sound-entry music assignment, following `Parser` and `Distributor::Distribute` in the pinned source. These operations are integrated into Harmonia's planner/runtime; the runtime MusicType factory is not included.
- **Combat Music Extender**: `SeaSparrowOG/CombatMusic`, commit `302c6df30348ce83cfcf72cbf6ae4e8681fcc7b6`. The source's AGPL-3.0 license and manifest are retained in `vendor/CME`; conflicting website metadata is not used as a relicensing basis. Version 0.7 adapts its six default-music call sites, six filters and matching priority in `CombatSelector.cpp`, `SelectorPlan.cpp` and `SelectorRules.h`. The runtime adds strict reference validation, preflight checks, ambiguous/unavailable-choice fallback and separate combat/cleared bookkeeping. It omits ActorUpdate polling and the optional combat-music fix. This adaptation is compiled into the DLL.
- Versions 0.1/0.2 contained broader MTD/CME adaptations. Version 0.3 removed them. Those historical trees remain in their tags; the current version does not mechanically re-add the old modules.
- **Native interfaces**: CommonLibSSE at `2415cc998b611d3f0ac15fcfeadca9c83b1bf7f8` and commonlib-shared at `29fbdb0e2dc548c9ab22f6964981d75090dc9094`. Native single-instance creation uses the engine's stateless factory. Local read-only executable inspection identified the 1.7.104 condition-holder pointer discrepancy and interface dispatch. No executable bytes or disassembly are included.
- **Native reader research only**: [Modex / ModExplorerMenu `Data::CacheCells`](https://github.com/patchulidev/ModExplorerMenu/blob/7035daece244aaddb2bbcca315d9d99f8df86af7/src/data/Data.cpp), commit `7035daece244aaddb2bbcca315d9d99f8df86af7`, and its attributed [Help Extender CELL reader](https://github.com/shad0wshayd3-TES5/BakaHelpExtender/blob/88eff7fb626718b1dde536dffff639382ce27cfc/src/ObScript/Help.cpp), commit `88eff7fb626718b1dde536dffff639382ce27cfc`, were compared with the pinned CommonLibSSE TESFile header/wrappers and Harmonia's shared reader. No code from these two readers was incorporated. The assessment and decision to retain the shared parser are in [AUDIT.md](AUDIT.md#modex-native-reader-assessment).
- **JsonCpp**: `open-source-parsers/jsoncpp`, commit `89e2973c754a9c02a49974d839779b151e95afd6`, statically linked for JSON parsing. Its license is included in the binary archive, along with CommonLibSSE/commonlib-shared, spdlog and zlib notices. All dependency pins are in `cmake/Dependencies.cmake`.
- **SimpleIni**: `brofield/simpleini`, commit `09c21bda1dc1b578fa55f4a005d79b0afd481296` (4.22), MIT license. Header-only UTF-8 INI parsing is compiled into the shared core; `LICENCE.txt` is included in the binary archive. No separate runtime DLL is added.
- **Music Replacer Reverter v1**: MadAborModding, Nexus 137806, file 578246. Downloaded previously for local verification; archive SHA-256 `7a4209dd4d9a4d58f832f8cafffd1a4b3fd1e39d45f8ea3ad9a810c1812c6420`. The existing local download was reused for 0.12: its BSA was unpacked privately to prepare the separate optional HQ resource archive. Reuse/modification permissions and credits, upstream UHDAP CC0 declaration, file mappings and omissions are recorded in [audio-pack/README.md](audio-pack/README.md). Neither its ESP nor its INI is shipped.
- Record layouts were checked against TES5Edit's `Core/wbDefinitionsTES5.pas`. Version 0.12 removes the original BSA reader and audio disk-cache writer entirely. Private build/verification tooling unpacks source archives once to establish mappings and fingerprints; players do not run it. Code/source archives contain code, docs, checks, metadata and licenses; the separately licensed optional ZIP contains audio.

Version 0.8 unified condition decoding, typed VMAD reference reading, playlist-local scene guards and audio preparation. Version 0.9 replaces scene-expression negation with inheritance of the author's added ordinary-track clauses, retains read-only scene expressions, and limits failure fallback to dependent uses. Actual Orsinium main/finale resources were read into a private test overlay for validation; neither resources nor raw proprietary records are distributed. The six CME-derived selector entry points remain attributed above; no additional upstream framework was merged.

Version 0.10 adds case-insensitive unique reference matching, official area evidence for test-named ambient lists, dependency-maximal track definitions, parent-Location scene evidence and restoration of exact authored battle/Boss memberships. Read-only condition schemas 117, 520 and 562 were checked against the local TES5Edit definition source. Verification used the locally installed 111-plugin combination and its audio/configurations, including actual Lorkhan, Bruma, ECSS and SIRENROOT resources. Only aggregate findings and synthetic fixtures are included in the repository.

Version 0.11 gives explicit membership/clear/area instructions priority over automatic inference. It follows the upstream native operations and parser conventions while retaining unique reference validation and pre-commit checks. Two syntax extensions are deliberate: whitespace-delimited INI end comments, and a deterministic clear-once/union rule when `Type` and `Type!` keys coexist. MTD stores those keys separately in a hash map, so their collision has no defined upstream execution order. Area assignment follows alphabetical files and last assignment per area. CME JSON comments, extra metadata and empty-filter behavior now follow its JsonCpp-based reader; duplicate keys and unresolved references still fail rather than weakening a rule. These are scoped adaptations, not a claim of complete framework equivalence or inherited runtime verification.

Version 0.12 introduces a bounded optional-resource manifest, verified atomic main/finale pairs and known stock/HQ content deduplication in the existing playlist preparation path. No audio assets are embedded in the DLL or Git repository. Only the explicitly attributed MRR/UHDAP source audio is distributed in the separate optional archive; no paid Creation, Lorkhan, regional-mod plugin/audio, Papyrus script or BSA is redistributed.
