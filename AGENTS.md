# Harmonia (UnifiedMusic internally)

- Keep a single DLL and an optional offline inspector. Do not add mod-name compatibility lists or redistribute game/Creation/music-pack assets.
- Keep one startup planner for playlist/condition restoration, additive existing-type MTD rules, proven regional guards, and field-only area recovery. Author-supplied CME selectors use six guarded entry points only; do not add polling, invented type relationships or new MusicTypes. Unsupported configuration operations pause writes; unresolved MTD tracks are diagnosed and skipped.
- Preserve scripted/Boss music, original condition expressions and deliberate deletions. New guards require unanimous ordinary-track exclusions and a pure geographic replacement; area repairs require one independent non-null assignment. Preserve ambiguous choices and dependent reversions.
- Guard shared singles with playlist-local native instances; retain other owners. Treat vanilla references to the public default battle list differently from mod-script ownership. Count configuration-only owners. Never flatten palettes or infer dedicated music from filenames.
- Original audio coexistence uses official BSA witnesses and engine-visible winning resources. Cache only validated original XWMA under music/harmonia; never overwrite existing audio or distribute cache files.
- Build Release DLL, inspector and HarmoniaRuleTests; run Python tests and CTest, and rerun real-plugin/config inspection after scanner changes. Runtime is restricted to Steam 1.7.104. The pinned SDK's BGSMusicTrack conditions field is actually a TESCondition pointer there; access through NativeTracks helpers.
- Offline checks do not prove runtime playback or save/reload correctness. Record that distinction in VALIDATION.md.
- Keep pinned upstream licenses and provenance. Never silently broaden supported executable versions.
